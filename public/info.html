Overview

INTLLM is a local-first AI runtime that extends compatible local models (served via Ollama) with layered memory, optional live web retrieval, controlled browser tools, and an OpenAI-compatible local API — all executing directly on your machine.

Standard local models operate in a vacuum: model → prompt → response. They lack long-term recall, verified real-time sources, controlled system capabilities, and clean client integration. INTLLM provides this missing surrounding environment while keeping user responses the highest priority.

  • Local First: The orchestrator, database, memory index, and UI run locally on 127.0.0.1.
  • Privacy by Default: Conversations, embeddings, and API keys remain on disk in PostgreSQL; nothing leaves your machine unless you explicitly trigger live web retrieval.
  • Model Agnostic: Dynamically detects installed models from your Ollama inventory.
  • Honest State Reporting: Dependency states (Ollama, PostgreSQL, pgvector) are transparently reported without fabrication.

Architecture

A unified FastAPI backend orchestrates all operations. User requests arriving via the React frontend, the CLI, or the /v1 OpenAI-compatible endpoint route through the same pipeline. 

User / Web UI / OpenAI-compatible API (/v1) / intllm CLI
                       │
                       ▼
         INTLLM Runtime (FastAPI Orchestrator)
    ┌─────────────┬──────────────┬──────────────────┐
    │             │              │                  │
    ▼             ▼              ▼                  ▼
 L0 Flash      L1 Hot        L2 Secondary       Tool Gateway
  Brain         Cache          Brain            · Browser Agent (Playwright)
 (Routing)     (30m TTL)     (pgvector)         · Web Retrieval (DuckDuckGo)

                       │
             ┌─────────┴─────────┐
             ▼                   ▼
       Ollama Daemon       PostgreSQL + pgvector
     (127.0.0.1:11434)   (Local Durable Storage)

A low-priority Background Learner maintains memory indexes and verifies freshness in idle cycles, yielding resources immediately when interactive queries arrive.

Layered Memory System

INTLLM performs knowledge indexing and retrieval, not model weight retraining. Relevant memory items are retrieved, scored, and injected into context before prompt transmission.

L0 Flash Brain

A fast routing index over the knowledge store backed by pgvector embeddings and keyword tables. Evaluates whether relevant knowledge exists, which tier holds it, and its confidence and freshness scores before running deeper searches.

L1 Hot Cache

Short-lived cache storing recently verified memory matches. Highly confident (≥ 55) and fresh (≥ 60) results are promoted here with a default 30-minute TTL, avoiding redundant vector distance calculations during ongoing discussions.

L2 Secondary Brain

The durable store in PostgreSQL with pgvector. Houses curated facts, workflows, lessons, and explicit user preferences. Every item records its source URL/citation, creation time, verification timestamp, and decay policy.

Model Runtime (Ollama)

INTLLM integrates with your local Ollama daemon at http://127.0.0.1:11434. It lists, pulls, and deletes models, and streams token completions via Server-Sent Events (SSE).

Any model supported by Ollama (Qwen, Llama, DeepSeek, Gemma, Mistral, Phi, etc.) functions out of the box. If Ollama is unreachable, the runtime returns an explicit 503 service_unavailable instead of failing silently.

Tool Gateway

The language model never possesses direct system privileges. All tool calls traverse a rigorous pipeline: Schema Validation → Policy Check → Permission Decision → Execution → Result Sanitization.

Tool Permission Level Default Status
web.search, web.extract Read-only Enabled (opt-in)
browser.read, browser.screenshot Read-only Enabled
browser.open, browser.click Approval Required Prompt User
brain.search, system.info Read-only Enabled
filesystem.read Workspace Allowlist Prompt User
filesystem.write, terminal.execute Critical / Restricted Disabled by Default

Browser & Live Internet

Live web retrieval (via DuckDuckGo or SearXNG) is strictly opt-in per request. Pass intllm_use_web: true in the API payload or enable the Web toggle in the UI. Retrieved content is sanitized and tagged with domain trust scores; local addresses and private subnets are blocked by SSRF filters.

The browser agent uses Playwright. If Playwright is not installed, the tool gateway reports it as unavailable rather than breaking the chat session.

OpenAI-Compatible Local API

Integrate third-party developer tools, editor extensions, or custom scripts by pointing them at http://127.0.0.1:8000/v1. 

GET  /v1/models                 # Lists installed Ollama models
GET  /v1/models/{model}         # Detailed model metadata
POST /v1/chat/completions       # Supports stream: true (SSE) and JSON

Example request using curl:

curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer intllm_your_local_key" \
  -d '{
    "model": "qwen2.5:7b",
    "messages": [{"role": "user", "content": "Explain vector memory"}],
    "stream": true,
    "intllm_use_brain": true,
    "intllm_use_web": false
  }'

API keys use salted scrypt hashing. The full key is displayed only once upon generation and can be revoked instantly.

Hardware Recommendation Tiers

INTLLM assesses local CPU, RAM, and GPU/VRAM to categorize models into recommendation tiers. These serve as guidance rather than artificial constraints:

Tier Target Specs Model Guidance
Potato iGPU, older CPUs, ≤ 8GB RAM Small quantized models (1B–3B), compact context window.
Nutral Mid-range discrete GPU, 16–32GB RAM 7B–14B models, moderate context, standard memory recall.
I Paid for My Whole PC High-end discrete GPU (≥ 16GB VRAM), 64GB+ RAM Large models (32B–70B), extended context, browser automation.

Security & Privacy

  • Localhost Binding: The API binds to 127.0.0.1 by default. Exposing it across a LAN requires explicit configuration.
  • Zero Remote Telemetry: No analytical beacons, crash pings, or background metrics are transmitted to any cloud server.
  • Secret Redaction: Auth tokens and API keys are automatically scrubbed from runtime logs and terminal output.
  • SSRF Guards: Live web retrieval rejects loopback, RFC 1918 subnets, and non-routable targets.
